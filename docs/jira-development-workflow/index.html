Jira Development Workflow

Standard Story and Bug delivery flow, owners, QA loop, and Play Store monitoring to Done.

Open interactive flowchart

Issue types

  • Story — planned product/feature work
  • Bug — defect fix

All tickets start in the Backlog as To Do.

Roles

RoleOwns
PMTo Do, Ready for Estimation
Tech LeadReady for Development, Ready to QA, Production Monitoring
DeveloperIn Progress, Code Review, Dev Done, Ready for Deployment
QAQA In Progress, QA Passed / Failed, Done

Story path

Backlog → To Do → Ready for Estimation → Ready for Development
→ In Progress → Code Review → Dev Done → Ready to QA → QA In Progress
→ QA Passed → Ready for Deployment → Production Monitoring → Done

Fail: QA Testing Failed → In Progress → Code Review → … (loop)

Bug path

Backlog → To Do → In Progress → Code Review → Dev Done
→ Ready to QA → QA In Progress
→ QA Passed → Ready for Deployment → Production Monitoring → Done

(Same fail loop. Skips estimation / ready for development.)

Key rules

  • Code Review stays until the PR is merged, even if review fails.
  • Dev Done only after merge.
  • Ready to QA is moved by Tech Lead.
  • Production Monitoring is Tech Lead after Play Store deploy.
  • Done is set by QA — only then is the sprint item complete.
